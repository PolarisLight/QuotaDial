# Codex Monitor 会话准确性与额度趋势设计

## 背景

当前面板已经能够读取账号级额度、统计本机 Codex 会话并给出耗尽预测，但真实数据
暴露出四类问题：

1. `codex-auto-review` 审批记录被错误识别为普通会话及主要模型。
2. GPT-5.5 缺少价格，且任意一个未定价事件会让整条会话显示“价格未知”。
3. 会话表只显示八条、没有内部纵向滚动，项目列过宽又迫使整表横向滚动。
4. 右侧每日 Token 图没有显示账号剩余额度的历史变化，也无法判断消耗速度。

本设计在不新增面板的前提下修正数据归属、定价和会话表，并把剩余额度折线叠加到
现有每日用量图中。

## 目标

- 审批模型只计入其所属会话的内部开销，不冒充主要模型。
- GPT-5.5 按官方标准价格计算等效 API 费用。
- 未定价的内部 Token 不再抹掉已经能够计算的费用。
- 会话表在固定区域内纵向滚动，默认展示更多记录且不需要横向滚动。
- 同一张图同时表达每日 Token 与账号剩余额度。
- 以七日额度均匀消耗速度为基准，标记当前消耗偏慢、正常或过快。

## 非目标

- 不监控社交媒体或预测 OpenAI 是否会主动重置额度。
- 不把多台设备上的会话明细伪装成账号级完整记录；额度仍是账号级，会话明细仍是
  当前设备可见的数据。
- 不新增独立图表卡片。
- 不尝试为没有公开价格的内部模型猜测费用。

## 会话归属

### Guardian 与 `codex-auto-review`

`codex-auto-review` 是 Codex 在审批或动作风险判断期间使用的内部 guardian 模型，
不是用户会话的主要模型。

新格式 guardian 元数据具有以下特征：

- `source.subagent.other == "guardian"`；
- `session_id` 与当前元数据的 `id` 不同；
- `session_id` 指向发起审批的用户会话。

解析器遇到这种记录时，把 `session_id` 作为父会话 ID。旧格式仍使用
`source.subagent.thread_spawn.parent_thread_id`。两种关系都沿现有父链归并到最终根
会话。

### 主要模型

主要模型按归并后 Token 权重选择，但以下内部模型不参加候选：

- `codex-auto-review`；
- 后续明确登记为 guardian、review 或系统审查用途的模型别名。

审批 Token 仍计入根会话的总 Token 和未定价 Token，只是不影响界面上的“模型”列。

若归并记录只包含内部审查模型且找不到有效父会话：

- 不把它展示为普通根会话；
- 保留在聚合统计中供诊断；
- 记录一次可观察的孤立内部会话计数，避免静默丢失。

## 定价

### GPT-5.5

内置价格目录补入 GPT-5.5 标准短上下文价格，每百万 Token：

- 输入：US$5.00；
- 缓存输入：US$0.50；
- 输出：US$30.00。

当前日志没有可靠的逐请求上下文长度信息，因此不自动套用长上下文价格。界面中的
费用继续明确标注为“等效 API 费用”，不是实际账单。

### 部分可定价

会话聚合不再使用“任意未知即全未知”的规则。每条会话分别累计：

- `equivalent_cost_usd`：所有已知价格事件的费用之和；
- `priced_tokens`：已经计价的 Token；
- `unpriced_tokens`：模型未知或没有公开价格的 Token。

显示规则：

- 全部可定价：`≈ US$X.XX`；
- 部分可定价：`≥ US$X.XX`，并在详情中显示 `N 未定价 Token`；
- 没有任何可定价 Token：`费用待定`，并显示未定价 Token 数；
- Token 为零：`US$0.00`。

这样 guardian 的内部开销不会把主要模型已经计算出的费用全部变成未知。

## 会话详情表

### 滚动

会话表使用固定高度的内部滚动区域：

- 桌面常规窗口最大高度约 320px；
- `overflow-y: auto`；
- `overflow-x: hidden`；
- 表头使用 `position: sticky` 固定在顶部；
- 不再截断为固定八条，当前已加载的根会话都可在区域内滚动查看。

滚动条使用系统原生样式，只调整宽度和轨道透明度，不制作悬浮胶囊滚动条。

### 列布局

表格使用固定布局，优先保证数值信息可见：

- 会话名称：弹性主列；
- 项目：约 104–120px；
- 模型：约 104px；
- Token：约 88px，右对齐；
- 等效费用：约 104px，右对齐；
- 最后活动：约 116px。

会话名称、项目和模型超长时单行省略，鼠标悬停通过 `title` 显示完整文本。展开行
继续展示完整项目路径和 Token 构成。窗口变窄时先压缩会话名称，不产生横向滚动。

## 每日用量与剩余额度组合图

### 图形

采用已确认的方案 A，并把额度方向改为“剩余额度”：

- 蓝色柱形：每天的 Token 用量；
- 暖白折线：账号剩余额度百分比；
- 折线从左向右随消耗逐渐下降；
- 绿色虚线：均匀消耗下的理想剩余额度；
- 淡绿色带：正常速度范围；
- 左侧纵轴服务于 Token 柱形，右侧隐式百分比轴服务于额度折线；
- 图例明确写“Token”“剩余额度”“正常速度”。

折线不使用红绿颜色表达当前数值，避免状态色污染主数据。速度结论由图表右上角的
状态标签表达。

### 历史数据

后端把当前额度周期的账号级观测序列加入 dashboard snapshot：

```text
QuotaHistoryPoint {
    observed_at: unix seconds,
    remaining_percent: 0..100
}
```

只发送当前 `limit_id + window_kind + reset segment` 的数据，并进行降采样：

- 保留周期首尾点；
- 每个自然日保留最后一个观测；
- 当天额外保留最新点；
- 最多发送 64 个点。

前端图表以最近七个自然日为横轴。每日 Token 柱来自账号 usage API；剩余额度折线
来自 rate-limit observations。两者按本地日期对齐，但保持独立纵轴。

如果只有一个额度观测点，仍显示 Token 柱和当前剩余百分比，不伪造历史折线，并
提示“正在积累额度样本”。

### 理想速度与状态

七日额度的均匀消耗基准为：

```text
100 / 7 = 14.2857 个百分点 / 天
```

正常带采用已确认的 ±20%：

```text
偏慢：低于 11.43 个百分点 / 天
正常：11.43–17.14 个百分点 / 天
过快：高于 17.14 个百分点 / 天
```

实际速度复用预测模块的稳健斜率思想，在当前额度周期内根据有效观测计算剩余额度
的中位下降斜率。小于零的重置跳变不参与同一段速度计算。

状态标签：

- `偏慢 · X%/天`
- `正常 · X%/天`
- `过快 · X%/天`
- 样本不足时显示 `正在积累样本`

绿色理想线从额度周期起点的 100% 下降到七日末的 0%。绿色带对应正常速度上下界，
并裁剪到 0–100%。这使图形和状态使用同一个基准。

### 异常与重置

- 检测到额度上升且形成新 reset segment 后，只绘制新段，不把跳变连成向上的折线。
- 账号额度读取失败时保留最后成功折线并沿用现有陈旧状态提示。
- usage API 缺少某天时该天 Token 柱为空，不补成虚假的零。
- 当前额度窗口不是七日时，不使用 `100/7` 标签；改用该窗口实际时长计算基准。

## 接口变化

`DashboardSnapshot` 增加：

- `quota_history: Vec<QuotaHistoryPoint>`；
- `quota_pace: Option<QuotaPace>`。

`QuotaPace` 包含：

- `percent_per_day`；
- `ideal_percent_per_day`；
- `status`：`slow | normal | fast`；
- `sample_count`。

`SessionSummary` 增加：

- `priced_tokens`；
- `unpriced_tokens`。

已有字段保持向后兼容，前端 mock 和测试数据同步补齐。

## 测试

### 后端

- guardian 新格式通过 `session_id` 归并到正确父会话；
- 旧格式 `thread_spawn.parent_thread_id` 仍然有效；
- `codex-auto-review` 不会成为主要模型；
- 无父级的纯 guardian 记录不出现在普通会话列表；
- GPT-5.5 输入、缓存输入和输出分别正确计价；
- 已知模型与未知模型混合时返回部分费用和未定价 Token；
- 当前 reset segment 正确降采样为额度历史；
- 额度上升不会跨 reset segment 连线；
- 速度阈值边界与非七日窗口计算正确。

### 前端

- 会话表不再只渲染八条；
- 表头固定且滚动区域存在；
- 表格不产生水平滚动；
- 项目列省略但保留完整 `title`；
- 部分可定价费用显示下界符号和未定价 Token；
- 组合图同时渲染 Token 柱与下降的剩余额度折线；
- 额度点从高到低时 SVG 纵坐标从上向下增加；
- 慢、正常、快三种标签正确；
- 样本不足时不生成伪造折线。

## 完成标准

1. 普通会话的主要模型不再显示 `codex-auto-review`。
2. GPT-5.5 会话能够显示等效费用。
3. 一个内部未定价事件不会让整条会话显示“价格未知”。
4. 会话表可纵向查看更多记录，且常规桌面宽度下无需横向滚动。
5. 现有右侧每日用量卡同时显示 Token 柱和逐渐下降的剩余额度折线。
6. 图表能用同一基准可靠标记消耗偏慢、正常或过快。
7. 多设备额度仍来自账号级接口，会话详情明确保持本机范围。

# Codex Monitor 会话详情、菜单栏与品牌升级设计

## 背景

当前版本已接入 Codex 账号级额度与 Token 数据，但“会话详情”仍是空状态，
菜单栏只提供少量操作，应用图标也与 Codex Pacer 的蓝底声波造型过于接近。
此外，额度图形需要明确表达“已消耗比例”：填充从左向右随消耗增长，而不是
用填充长度表示剩余额度。

本轮升级同时解决以下问题：

1. 从本机 Codex 会话记录生成真实、可核对的会话详情。
2. 将子代理的新增用量归并到所属顶层会话，避免继承历史重复计数。
3. 让菜单栏承担日常查看与刷新操作，减少频繁打开完整面板的需要。
4. 使用独立的“余量窗口”视觉标识，替换当前类似 Codex Pacer 的图标。
5. 统一额度可视化语义，绿色填充只代表已经消耗的比例。

## 范围与数据边界

账号额度与跨设备总 Token 继续来自 Codex 官方账号级接口。它是剩余额度、
重置时间和跨设备总量的唯一权威来源。

会话详情来自当前设备的本地 Codex 会话文件，因此只能解释本机可归因的 Token。
其他设备产生的用量会进入账号级总量，但不会伪装成本机会话。未来可在其他设备
安装监控端并增加同步层；本轮不实现跨设备会话明细同步。

界面必须明确区分：

- “所有设备”：账号额度、官方日 Token 总量。
- “本机记录”：会话列表、项目归属、模型分布与等效 API 费用。

## 方案选择

采用完整本地会话导入器，而不是只读取当前 app-server 会话或进行简单文件求和。

导入器读取活动与归档会话 JSONL，维护增量游标，并按稳定事件标识去重。它先构建
会话谱系，再将每个事件的新增用量归属到顶层用户会话。继承的上下文只作为关系
证据，不重复计入子会话。

## 会话导入架构

### 文件发现

导入器扫描 Codex 的活动会话与归档会话目录。每个文件记录规范化路径、文件标识、
已处理字节偏移、文件长度与修改时间。

首次启动执行完整导入；后续启动和文件变化只读取新增内容。监视事件仅用于加速，
定期低频扫描负责修复遗漏。

### 重写与截断

出现以下任一情况时，文件从头重放：

- 文件长度小于已记录偏移；
- 文件标识变化；
- 已处理区域的校验信息不匹配。

重放不会重复增加用量，因为规范化事件在持久层具有稳定唯一键。

### 规范化事件

每条可计费用量记录至少保存：

- 来源文件与稳定事件标识；
- Codex 会话 ID；
- 发生时间；
- 模型；
- 输入、缓存输入、输出和推理 Token；
- 父会话或生成来源线索；
- 项目路径与会话标题线索。

无法解析的行不会终止整个文件导入。应用记录文件、偏移与错误摘要，并继续处理
后续完整行；不把损坏行计入统计。

### 谱系与归并

会话之间建立父子关系，并解析到一个顶层用户会话。归并规则如下：

1. 顶层会话产生的增量 Token 计入自身。
2. 子代理开始之后新产生的 Token 计入所属顶层会话。
3. 子代理继承的父级历史不再次计入。
4. 同一规范化事件无论被重放、归档或重新发现，都只计入一次。
5. 暂时无法确定父级的会话独立显示；关系补齐后重新归并，不复制事件。

### 等效费用

等效 API 费用根据事件发生时的模型和 Token 分类计算。价格表必须带版本和生效
时间；未知模型显示 Token，但费用显示为“价格未知”，不能按其他模型猜测。

费用仅表示按照公开 API 价格换算的参考值，不表示用户实际账单。

## 会话详情界面

“会话详情”区域不再显示占位提示。每行代表一个顶层用户会话，子代理不单独占行。

默认按最后活动时间降序展示，包含：

- 会话标题；
- 项目名称或路径；
- 最后活动时间；
- 主要模型；
- 总 Token；
- 等效 API 费用；
- 子代理数量（仅作为次要标记）。

点击一行展开组成明细，展示输入、缓存输入、输出、推理 Token 和模型分布。界面
使用“会话详情”等用户语言，不在标题或说明中强调“根会话”“继承历史”等内部
会计术语。

空状态仅在本机没有可导入记录时出现，并明确写“本机尚未发现会话记录”。导入
失败时显示可操作的错误状态和重新扫描入口，不能把失败伪装成零用量。

## 额度可视化

主额度卡使用水平进度条：

- 大数字优先显示“剩余 75%”；
- 进度条填充长度表示“已消耗 25%”；
- 填充从左向右随已消耗比例增长；
- 进度条下方同时标注“已消耗 25%”和“剩余 75%”；
- 超过安全阈值时改变强调色，但宽度最大限制为 100%。

环形图不用于主额度卡。累计折线图只用于消耗速度或预测，不与剩余额度共用同一
视觉编码。

## 菜单栏

菜单栏标题继续显示整数剩余百分比；陈旧数据追加问号。菜单展开后包含：

1. 不可点击的状态区：剩余比例、已消耗进度条、重置时间、耗尽预测。
2. 不可点击的摘要：今日 Token、本机活跃会话数、最近更新时间。
3. 操作：打开面板、查看最近会话、立即刷新。
4. 应用项：设置、退出 Codex Monitor。

“查看最近会话”打开主窗口并滚动或聚焦到会话详情区域。刷新操作必须异步执行，
避免阻塞菜单；刷新进行中禁用重复触发。无账号数据时显示“等待账号数据”，本机
会话统计仍可独立展示。

菜单状态随新的 dashboard snapshot 更新。菜单显示的百分比、重置时间和预测必须
与主面板使用同一个格式化函数，避免两处口径不一致。

## 品牌与图标

采用已确认的第 2 套“余量窗口”：

- 彩色应用图标为深绿色圆角底板与抽象余量窗口；
- 窗口内的上升液面表达额度状态，但不绘制声波、竖向音频条或 Codex Pacer 的蓝色
  渐变方块；
- macOS 菜单栏使用独立的单色模板版本，保留窗口轮廓与简化液面；
- 生成 macOS、Windows 和前端 favicon 所需尺寸，保持同一轮廓；
- 小尺寸优先识别度，不把文字或百分比写入图标。

图标资产必须由项目内的矢量母版导出，避免不同平台版本逐渐偏离。

## 持久化

在现有 SQLite 中增加以下逻辑表：

- 导入文件状态；
- 规范化 Token 事件；
- 会话元数据；
- 会话谱系；
- 模型价格版本。

写入在事务中完成。事件唯一键与文件游标同时提交，避免应用崩溃后出现“游标已前进
但事件未落库”的数据缺口。

数据库迁移必须可重复执行，并保留已有账号观测记录。

## 错误处理与诊断

- 单个文件不可读：记录错误并继续其他文件。
- 单行 JSON 损坏：记录位置并跳过该行。
- 谱系暂时缺失：独立显示，后续自动修复。
- 未知模型价格：保留 Token，费用不估算。
- 数据库事务失败：不推进文件游标。
- 官方账号接口失败：保留最后一次账号快照并标记陈旧，本机会话导入继续运行。

设置页后续可展示最近导入时间、扫描文件数、跳过行数和最后错误；本轮至少在后端
保留这些诊断字段，并让会话区域能够区分空数据与导入失败。

## 测试策略

### Rust 单元与集成测试

- 活动、归档、截断和重写文件；
- 顶层会话、子代理、缺失父级和延迟补齐；
- 继承历史不重复计费；
- 同一事件重放后仍只出现一次；
- 多模型 Token 分类与价格版本；
- 未知价格不产生虚假费用；
- 菜单栏状态与主面板格式一致；
- 旧数据库迁移后账号观测仍存在。

### React 测试

- 会话列表一行对应一个顶层会话；
- 子代理用量包含在所属会话总量中，但不独立占行；
- 展开行显示 Token 分类；
- 空状态与错误状态不同；
- 主额度条以已消耗百分比设置宽度；
- 菜单“查看最近会话”聚焦正确区域。

### 手工验证

- 使用真实本机会话目录对照若干会话的 Token；
- 重启、归档和追加会话文件后总量不跳增；
- macOS 深浅菜单栏下单色图标均清晰；
- 菜单刷新不冻结界面；
- 账号额度仍覆盖其他设备，而会话区域明确标注“本机记录”。

## 完成标准

1. 会话详情显示真实本机数据，不再是占位内容。
2. 每个顶层用户会话只出现一行，子代理新增用量正确归并。
3. 文件重放、归档或继承历史不会导致 Token 重复计数。
4. 菜单栏无需打开主窗口即可查看核心状态并执行刷新。
5. 主额度条从左向右表示已消耗比例。
6. 应用与菜单栏均使用“余量窗口”图标，不再类似 Codex Pacer。
7. 账号级额度继续以官方数据为准，并与本机会话范围清晰区分。
